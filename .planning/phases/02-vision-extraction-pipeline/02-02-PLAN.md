**Identical to text route (copy these patterns verbatim):**
- Auth guard: `const { userId } = await auth()` + 401 if not authenticated
- Supabase client setup: `createClient()` and `createAdminClient()`
- FormData parsing with try/catch returning 400 on failure
- `projectId` UUID validation regex check
- SSE TransformStream + TextEncoder + writer setup
- `writerClosed` flag + `closeWriter()` helper
- `sendProgress` callback pattern (same ProgressCallback signature)
- Project creation when `projectId` is null (insert into `projects` table with `user_id`, `name`, `status: 'in_progress'`)
- `documentId = crypto.randomUUID()` + `storagePath = \`${userId}/${projectId}/${documentId}/${file.name}\``
- Supabase Storage upload via `adminSupabase.storage.from('financial-documents').upload(...)`
- Document record insert: `supabase.from('documents').insert({ id: documentId, project_id, user_id, file_name, original_file_name, file_type, file_size, storage_path, processing_status: 'processing' })`
- Download from Storage for processing: `adminSupabase.storage.from('financial-documents').download(storagePath)`
- Year conflict detection: `detectYearConflicts()` + `conflict_detected` SSE event
- Fresh Supabase client after long-running operation: `const freshSupabase = await createClient()`
- Extraction insert into `extractions` table with same fields: `extraction_data`, `fiscal_years`, `latest_fccr`, `latest_dscr`, `latest_senior_debt_to_ebitda`, `latest_debt_to_capital`, `latest_adjusted_ebitda`, `quantitative_risk_score`, `quantitative_risk_band`, `validation_issues`, `processing_time_ms`
- Project update with `risk_score` and `risk_band` when `quantitativeRiskAssessment` is present
- `complete` SSE event with same `data` shape: `{ message, filename, projectId, documentId, extractionId, financialMetrics }`
- `updateDocumentStatus()` helper function (copy exactly)
- SSE response headers: `Content-Type: text/event-stream`, `Cache-Control: no-cache`, `Connection: keep-alive`

**Differences from text route:**

1. **PDF-only validation** — after parsing FormData and before creating the project or anything else,
   check the file type. If it is not a PDF, return immediately:
   ```typescript
   if (file.type !== 'application/pdf' && !file.name.toLowerCase().endsWith('.pdf')) {
     return NextResponse.json(
       { error: 'Vision extraction only supports PDF files. For Excel or Word documents, use /api/extractData.' },
       { status: 400 }
     );
   }
   ```
   This check happens BEFORE the SSE stream is opened (the stream is not needed for validation errors).

2. **No temp file** — the text route writes to a temp file and passes the path to `extractFinancialData()`.
   The vision route downloads the file from Supabase Storage directly into memory as a Buffer and passes
   it to `extractVisionData()`. Do not write any temp file. Pattern:
   ```typescript
   const fileData = ... // from adminSupabase.storage download
   const pdfBuffer = Buffer.from(await fileData.arrayBuffer());
   const extractedData = await extractVisionData(pdfBuffer);
   ```

3. **Different progress stages** — the text route sends many intermediate stages. The vision route
   sends these stages only:
   - `{ stage: 'uploading', progress: 5, message: 'Uploading file...' }`
   - `{ stage: 'uploading', progress: 8, message: 'Storing file...' }`
   - `{ stage: 'uploading', progress: 10, message: 'File uploaded successfully' }`
   - `{ stage: 'extracting', progress: 20, message: 'Converting PDF pages to images...' }`
   - `{ stage: 'computing', progress: 75, message: 'Computing financial ratios...' }` (send this AFTER extractVisionData returns)
   - `{ stage: 'saving', progress: 90, message: 'Checking for conflicts...' }`
   The vision processor handles per-page progress internally (logs to console). The route does not
   attempt to stream per-page events — extractVisionData() is called as a single awaited call.

4. **No ProgressCallback parameter** — extractVisionData(pdfBuffer) takes only a Buffer.
   Do not pass sendProgress to it. The progress events before and after the call are sent manually.

5. **Caller identification in log messages** — use 'API Hit: /api/extractData/vision' in the
   initial console.log to distinguish from the text route in server logs.

6. **Import extractVisionData** from '@/utils/visionProcessor', not from '@/utils/aiProcessor'.

After writing the file, also create the directory if it doesn't exist:
`app/api/extractData/vision/` (the file creation will implicitly create it, but verify the path).
