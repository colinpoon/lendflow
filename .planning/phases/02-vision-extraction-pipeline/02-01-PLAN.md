<task type="auto">
  <name>Task 1: Create utils/visionProcessor.ts</name>
  <files>utils/visionProcessor.ts</files>
  <action>
Create utils/visionProcessor.ts with a single exported async function extractVisionData(pdfBuffer: Buffer).

The function signature must match the ExtractionResult interface from utils/aiProcessor.ts
(metrics_by_year, riskAssessment, debtHealthAssessment, quantitativeRiskAssessment,
validation_issues, extraction_warnings). Export the type as VisionExtractionResult (aliased to
ExtractionResult from aiProcessor.ts to ensure shape compatibility).

Implementation steps, in order:

1. **Validate API key** — call validateApiKey() from lib/vision/claude-client.ts at the top of
   the function body. If it throws, let it propagate (the route will catch and send SSE error).

2. **Run vision extraction** — call extractFromPdf(pdfBuffer) from lib/vision (use the Buffer
   overload, not the file path). This returns PdfExtractionResult with metricsByYear:
   Record<string, ExtractedMetrics>. Use page-by-page processing (extractFromPdf already does this
   internally — do NOT re-implement page iteration here).

3. **Guard empty result** — if pagesProcessed === 0 or Object.keys(metricsByYear).length === 0,
   throw new Error('Vision extraction returned no metrics. Document may not contain financial tables.');

4. **Normalize fiscal year keys** — Claude may return keys like "FY2023", "2023Q4",
   "December 31, 2023", or "2023". Normalize all keys to four-digit year strings before calling
   computeVisionMetrics(). Use this normalization logic:
   ```typescript
   function normalizeFiscalYear(raw: string): string {
     // Match four consecutive digits anywhere in the string
     const match = raw.match(/\b(20\d{2}|19\d{2})\b/);
     return match ? match[1] : raw; // Fall back to raw if no year found
   }
   ```
   If two different raw keys normalize to the same year, keep the one whose raw value appears later
   in Object.entries() order (simple last-wins merge to match Phase 1 pattern).

5. **Compute derived metrics per year** — implement a private computeVisionMetrics(m: ExtractedMetrics):
   ComputedMetrics function that mirrors the computeMetrics() function in utils/aiProcessor.ts exactly.
   Import and call these functions from lib/calculations.ts in this order:
   - calculateDebtMetrics(m) → senior_debt, total_debt, debt_breakdown
   - calculateEBITDA(m) → ebitda (assign to result.ebitda if m.ebitda is null)
   - calculateAdjustedEBITDA(ebitda, m) → adjusted_ebitda, calculated_adjusted_ebitda, adjusted_ebitda_breakdown
   - calculateFCCR(result.adjusted_ebitda ?? result.ebitda, m) → fccr, fccr_numerator, total_fixed_charges, cash_flow_for_debt_servicing, fccr_breakdown
   - calculateTotalDebtToCapital(result.total_debt, result.shareholders_equity) → total_debt_to_capital
   - calculateSeniorDebtToEBITDA(result.senior_debt, result.adjusted_ebitda ?? result.ebitda) → senior_debt_to_ebitda
   - calculateInterestCoverageRatio(result.ebitda, result.interest) → interest_coverage_ratio
   - calculateDebtToEquityRatio(result.total_debt, result.shareholders_equity) → debt_to_equity_ratio
   - calculateCurrentRatio(result.current_assets, result.current_liabilities) → current_ratio
   - calculateDSCR(result.adjusted_ebitda ?? result.ebitda, result) → dscr, funded_debt, funded_debt_to_ebitda, dscr_breakdown

   Do NOT copy-paste the debug console.log() blocks from aiProcessor.ts. The vision processor
   should be clean — log only completion and error states.

6. **Build computed map** — iterate over normalized metricsByYear, call computeVisionMetrics() per
   year, collect into Record<string, ComputedMetrics>.

7. **Validate metrics** — use the same validation logic as aiProcessor.ts validateMetrics():
   check expenses > revenue and non-finite ratio values. Return validation_issues as
   Record<string, string[]>.

8. **Generate risk assessments** — call in sequence:
   - generateRiskAssessment(computed) → riskAssessment
   - generateDebtHealthAssessment(computed) → debtHealthAssessment
   - calculateQuantitativeRisk(computed) → quantitativeRiskAssessment
   All three are already imported/available from lib/risk-generator.ts and lib/quantitative-risk.ts.

9. **Build extraction_warnings** — include:
   - "Vision extraction processed N pages" (always include for transparency)
   - "N fiscal year keys could not be normalized to a 4-digit year" (if any raw keys had no year match)
   - Any other warnings as strings

10. **Return ExtractionResult** — shape must match ExtractionResult from utils/aiProcessor.ts:
    ```typescript
    return {
      metrics_by_year: computed,         // Record<string, ComputedMetrics>
      riskAssessment,                    // RiskData | null
      debtHealthAssessment,             // DebtHealthAssessment | null
      quantitativeRiskAssessment,       // QuantitativeRiskAssessment | null
      ...(Object.keys(validationIssues).length > 0 && { validation_issues: validationIssues }),
      extraction_warnings: warnings,
      // No chunk_stats or merge_conflicts — not applicable to vision pipeline
    };
    ```

Do NOT accept a file path string. The route will handle temp file → Buffer conversion. Accept Buffer only.
Do NOT import or call extractFinancialData() from aiProcessor.ts. These are parallel, independent pipelines.
Do NOT export computeVisionMetrics() — it is a private implementation detail.
