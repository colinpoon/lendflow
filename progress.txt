### Task 3: Audit & Fix Calculation Engine (COMPLETED)
Full audit of all 7 calculator modules. Fixed 4 high-priority bugs:

1. **ebitda-calculator.ts** — `usedGrossFallback` flag stayed `false` when the P&L interest field was `null` (absent) rather than negative. When a fallback source (e.g. `cash_interest_paid`) was used in this case, downstream `calculateAdjustedEBITDA` would still subtract interest income, causing a double-deduction and understated Adjusted EBITDA. Fix: set flag unconditionally whenever a fallback is used.

2. **fccr-calculator.ts** — `distributions_paid` was extracted but never deducted from the FCCR numerator. This systematically overstated FCCR for owner-operated businesses paying dividends/draws. Fix: deduct `distributionsPaid` from numerator alongside `capexDeduction` and `cashTaxesPaid`.

3. **ratio-calculator.ts** — Three distress conditions returned `null` instead of the actual (potentially negative or >100%) ratio: `calculateTotalDebtToCapital` with negative equity, `calculateSeniorDebtToEBITDA` with negative EBITDA, and `calculateDebtToEquityRatio` with negative equity. These nulls masked critical signals from lenders. Fix: removed the early-return guards; ratios are now computed and returned regardless of sign.

4. **recalculate.ts** — DSCR/funded_debt was not recalculated when covenant config changed. After recalculating FCCR and senior debt, the DSCR breakdown panel showed stale funded debt values. Fix: added `calculateDSCR` call in the recalculation loop, updating `m.dscr`, `m.funded_debt`, `m.funded_debt_to_ebitda`, and `m.dscr_breakdown`.

### Task 2: Cross-Reference Validation Checks (Completed)
Added 3 new checks to `validateArithmeticConsistency` in `lib/extraction-merger.ts`:

1. **Interest expense cross-reference** — Compares P&L `interest` field against `fixed_charges.total_interest_expense`. Flags >10% variance with a note that one value may be net of interest income, prompting analyst review before FCCR computation.

All warnings surface in `extraction_warnings` for analyst review; none alter extracted values (non-corrective).

### Task 5: Regression Testing with Financial Reports (COMPLETED)
Created `scripts/test-extraction.ts` — a full CLI test harness for regression testing extraction output.

Key design decisions:
1. **Snapshot testing** — On first run, saves extracted key metrics (revenue, net_income, adjusted_ebitda, fccr, dscr, total_debt, senior_debt, senior_debt_to_ebitda, total_debt_to_capital, current_ratio) to `test-results/snapshots/<filename>.json`. Subsequent runs compare against snapshots and flag >5% changes as regressions.

2. **Ground truth integration** — Uses existing `lib/benchmarks/ground-truth.ts` for verified baselines where available. GT values of `0` are skipped (unverified placeholder). Thresholds: <5% = PASS ✓, 5-20% = WARN ⚠, >20% = FAIL ✗.

3. **CLI flags**: `--update` to refresh snapshots, `--file <pattern>` to filter files, `--dry-run` to list files without calling API.

4. **Edge case documentation** — `KNOWN_EDGE_CASES` map documents 8 known tricky files inline (Parkland large-cap, PBHC banking institution, Taiga Canadian thousands, etc.).

5. **Exit code** — Returns 1 if any GT failure or snapshot regression detected; 0 otherwise. Suitable for CI integration.

6. **npm script** — Added `"test:extraction": "tsx scripts/test-extraction.ts"` to package.json.

### Task 10: Extraction Pipeline Robustness (COMPLETED)
All 3 items implemented across `lib/extraction-merger.ts` and `utils/aiProcessor.ts`:

1. **Scale over-correction prevention** — `ScaleNormalizationResult` now carries a `correctedYears?: Set<string>`. Pass 1 (`applyDetectedScale`) populates this set for every year it uniformly scales. Pass 2 (`validateCrossMetricScale`) and Pass 3 (`normalizeScaleMismatch`) both accept an `alreadyCorrectedYears` parameter and skip years already corrected — eliminating the ×1000 then ÷1000 double-correction that could silently net to the wrong scale on some documents. `aiProcessor.ts` threads the set through all three passes.

2. **Fiscal year key normalization** — New `normalizeFiscalYearKeys<T>()` function runs immediately after `mergeExtractionsWithConflicts` in `aiProcessor.ts`. Normalises common AI variants: `FY2023` → `2023`, `2023E/A/F/P` → `2023`, `2022/23` → `2023` (short overlap), `2023/2024` → `2024` (full overlap). Invalid formats (non-parseable) are dropped with an analyst-visible warning. Duplicate year keys (two variants resolving to the same year) keep the first entry and warn. Year range restricted to 1900–2099.

3. **Warnings array cap** — After all warnings are accumulated (conflicts, scale corrections, arithmetic, AI reconciliation), the array is capped at 50 entries. Overflow is summarised as `"...and N more warnings (set DEBUG_FINANCIALS=true for full list)"`. Prevents UI/storage overload on complex multi-chunk documents.

### Task 12: Fix Revolver Gross-Draw Distortion in DSCR Denominator (COMPLETED — commit 9d98846)
Surfaced existing server-side revolving credit warning to analysts in the UI.

Problem: `repayment_of_debt` (US GAAP cash flow financing activities) can include gross revolving
credit draws AND repayments in the same period. A company drawing and fully repaying a $20M revolver
inflates this line with gross activity, overstating the DSCR/FCCR denominator and understating
coverage. The server was already detecting this with `console.warn` — analysts never saw it.

Changes:
1. **`debt-service-resolver.ts`** — Added `warnings: string[]` to `ResolvedDebtService`. Upgraded
   the existing console.warn to also push a clear analyst-facing message to warnings. Added a second,
   stronger check: when `repayment_of_debt > revolving_credit_facilities * 3`, warn that gross
   revolving activity is almost certainly inflating the denominator.
2. **`dscr-calculator.ts`** / **`fccr-calculator.ts`** — Added `warnings: string[]` to
   `DSCRCalculationResult` and `FCCRCalculationResult`. Propagated warnings on all return paths.
3. **`utils/aiProcessor.ts`** — Changed `computeMetrics` return type to `{ metrics, warnings }`.
   Deduplicated warnings from FCCR and DSCR paths. Pushed to `extractionWarnings` so they appear
   in the ExtractionWarnings UI panel.

### Task 12 + Task 16: Add preferred dividends to FCCR denominator (COMPLETED — commit 0b2d7be)
`FixedCharges.preferred_dividends` was extracted by the AI but never included in the FCCR denominator,
causing FCCR to be overstated for any borrower with preferred equity.

Design decision: `preferredDividends` added as a separate named field in `ResolvedDebtService` (NOT
folded into `total`) so that DSCR (banker's ratio) is unaffected. FCCR explicitly adds it to its
denominator, which is correct per commercial lending convention. The critical distinction is preserved:
- `distributions_paid` (common equity draws) = FCCR **numerator** deduction
- `preferred_dividends` (contractual senior obligation) = FCCR **denominator** addition

Files changed:
- `lib/calculations/debt-service-resolver.ts` — `preferredDividends` field + `preferred_dividends_value` in sources
- `lib/calculations/fccr-calculator.ts` — added to `totalDebtService`, exposed in `fccr_breakdown`
- `types/financial.ts` — `preferred_dividends?: number` in `FCCRBreakdown`, `preferred_dividends_value` in sources

- TypeScript: clean (tsc --noEmit, 0 errors)
