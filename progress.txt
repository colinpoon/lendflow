### Task 3: Audit & Fix Calculation Engine (COMPLETED)
Full audit of all 7 calculator modules. Fixed 4 high-priority bugs:

1. **ebitda-calculator.ts** — `usedGrossFallback` flag stayed `false` when the P&L interest field was `null` (absent) rather than negative. When a fallback source (e.g. `cash_interest_paid`) was used in this case, downstream `calculateAdjustedEBITDA` would still subtract interest income, causing a double-deduction and understated Adjusted EBITDA. Fix: set flag unconditionally whenever a fallback is used.

2. **fccr-calculator.ts** — `distributions_paid` was extracted but never deducted from the FCCR numerator. This systematically overstated FCCR for owner-operated businesses paying dividends/draws. Fix: deduct `distributionsPaid` from numerator alongside `capexDeduction` and `cashTaxesPaid`.

3. **ratio-calculator.ts** — Three distress conditions returned `null` instead of the actual (potentially negative or >100%) ratio: `calculateTotalDebtToCapital` with negative equity, `calculateSeniorDebtToEBITDA` with negative EBITDA, and `calculateDebtToEquityRatio` with negative equity. These nulls masked critical signals from lenders. Fix: removed the early-return guards; ratios are now computed and returned regardless of sign.

4. **recalculate.ts** — DSCR/funded_debt was not recalculated when covenant config changed. After recalculating FCCR and senior debt, the DSCR breakdown panel showed stale funded debt values. Fix: added `calculateDSCR` call in the recalculation loop, updating `m.dscr`, `m.funded_debt`, `m.funded_debt_to_ebitda`, and `m.dscr_breakdown`.

### Task 2: Increase Extraction Accuracy (Partial — prompt engineering + merge improvements)
Improved extraction accuracy via targeted prompt engineering and merger validation:

1. **extraction-prompt.ts — Multi-year column pinning** — Added `MULTI-YEAR COLUMN DISCIPLINE` rule. The AI now traces every value to the column header matching the year key being populated, preventing cross-year contamination in comparative financial statements.

2. **extraction-prompt.ts — D&A arithmetic self-verification** — Added required arithmetic evidence block inside the depreciation section. AI must compute `sum(sub-components)`, compare to its aggregate figure, and emit the evidence in `_sources["depreciation_amortization"]`. Prefers CF add-back as the authoritative aggregate when sub-components mismatch.

3. **extraction-prompt.ts — Expanded IFRS synonyms** — `cash_taxes_paid` now covers IFRS/ASPE/Canadian variants ("Tax paid", "Income tax instalments paid", "Current tax paid"). `distributions_paid` covers trust/private-company variants ("Distributions to unitholders", "Owner draws", "Drawings") with explicit exclusions for preferred/NCI dividends.

4. **extraction-prompt.ts — Lease liability principal clarification** — `payment_of_lease_liability` now clearly specifies principal-only (IFRS 16 balance-sheet liability reduction), with explicit exclusion of interest-on-leases, operating-activity short-term payments, and maturity schedule totals. Explains downstream FCCR/DSCR impact.

5. **extraction-merger.ts — D&A component identity check** — Implemented `validateArithmeticConsistency` D&A sub-component validation. Detects impossible aggregates (below sub-component sum) and missing D&A categories (aggregate >150% of sub-sum when 2+ components found). Surfaces in `extraction_warnings` for analyst review.

6. **reconciliation-prompt.ts — Year-column awareness** — Reconciler now explicitly uses left-column/right-column convention to diagnose year-swap conflicts and prefers sources with explicit year-column evidence.

### Task 2: Cross-Reference Validation Checks (Completed)
Added 3 new checks to `validateArithmeticConsistency` in `lib/extraction-merger.ts`:

1. **Interest expense cross-reference** — Compares P&L `interest` field against `fixed_charges.total_interest_expense`. Flags >10% variance with a note that one value may be net of interest income, prompting analyst review before FCCR computation.

2. **Income statement identity** — Validates that `revenue - expenses - interest - taxes ≈ net_income` (per extraction prompt, `expenses` = total operating costs, excl. interest & taxes). Variance normalised by revenue (not net_income) to avoid false positives on near-zero net income. Flags >5% variance.

3. **Reported adjusted EBITDA plausibility** — If the document includes `reported_adjusted_ebitda` (company's own published figure), compares it against calculated EBITDA base (NI + I + T + D&A). Flags >40% gap as an `Info` warning recommending review of `adjusted_ebitda_components`.

All warnings surface in `extraction_warnings` for analyst review; none alter extracted values (non-corrective).

### Task 5: Regression Testing with Financial Reports (COMPLETED)
Created `scripts/test-extraction.ts` — a full CLI test harness for regression testing extraction output.

Key design decisions:
1. **Snapshot testing** — On first run, saves extracted key metrics (revenue, net_income, adjusted_ebitda, fccr, dscr, total_debt, senior_debt, senior_debt_to_ebitda, total_debt_to_capital, current_ratio) to `test-results/snapshots/<filename>.json`. Subsequent runs compare against snapshots and flag >5% changes as regressions.

2. **Ground truth integration** — Uses existing `lib/benchmarks/ground-truth.ts` for verified baselines where available. GT values of `0` are skipped (unverified placeholder). Thresholds: <5% = PASS ✓, 5-20% = WARN ⚠, >20% = FAIL ✗.

3. **CLI flags**: `--update` to refresh snapshots, `--file <pattern>` to filter files, `--dry-run` to list files without calling API.

4. **Edge case documentation** — `KNOWN_EDGE_CASES` map documents 8 known tricky files inline (Parkland large-cap, PBHC banking institution, Taiga Canadian thousands, etc.).

5. **Exit code** — Returns 1 if any GT failure or snapshot regression detected; 0 otherwise. Suitable for CI integration.

6. **npm script** — Added `"test:extraction": "tsx scripts/test-extraction.ts"` to package.json.
